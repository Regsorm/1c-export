# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [Unreleased]

### Добавлено

- Режим `changeDetection = sql` в watch: обнаружение изменений конфигурации, расширений и допобработок опросом служебных таблиц MS SQL, без HTTP-сервиса в базе (по умолчанию).
- GUI: журнал шагов запуска и работы в `logs/gui-ГГГГ-ММ-ДД.log` рядом с exe.
- Уровни журнала `info`/`debug`, поле `logLevel` в `bases.json` и `config.json`; шаги запуска GUI пишутся только на `debug`.
- Параметр `gitAutocrlf` в `bases.json` и `config.json` — значение `core.autocrlf` для git-команд программы (`false` по умолчанию; допустимы `true`, `input` и пустая строка) — и выбор на вкладке «Выгрузка» GUI.

### Изменено

- Команды git программы всегда идут с `gc.auto=0`: автоматическая упаковка не запускается посреди коммита, упаковкой управляет `gitGcAfterPush`.
- `mcpUrl` и `mcpApiKey` обязательны только при `changeDetection = eventlog`.
- Бинарные снимки `_artifacts/` (`.cf`/`.cfe`) сохраняются только при `saveArtifacts: true` / `--save-artifacts`; по умолчанию выключено.
- В режиме watch с `changeDetection = sql` снимок `_artifacts/base.cf` обновляется только когда менялась основная конфигурация; при первом снимке и при полной перезаписи базы он пишется всегда.

### Исправлено
- Удаление последнего расширения из базы не убирало его папку `extensions/<Имя>/` и `.cfe`: при пустом списке расширений выгрузка выходила раньше сравнения с прошлым состоянием.
- В журнал не пишется `error: No such remote 'origin'` при первом коммите в свежий репозиторий.

- GUI: зависание при запуске из-за двух версий comctl32 в процессе — в exe встроен манифест с зависимостью от Common-Controls 6.0.

## [3.0.0] — 2026-09-03

Первый публичный выпуск.

### Добавлено

- Три режима работы в одном исполняемом файле: GUI без аргументов, CLI с ключами, служба `watch --bases bases.json`.
- Выгрузка основной конфигурации через `ibcmd infobase config export` с инкрементальным режимом `--sync` и автоматическим `--force` при первой выгрузке в пустую папку.
- Инкрементальная выгрузка расширений по контрольным суммам из `config extension list`; удалённые из базы расширения удаляются из папки.
- Бинарные снимки `_artifacts/base.cf` и `_artifacts/extensions/<имя>.cfe` через `ibcmd config save`.
- Выгрузка справочника `ДополнительныеОтчетыИОбработки` напрямую из MS SQL Server (TDS) с распаковкой `ХранилищеЗначения`, сверкой MD5 по `КонтрольнаяСумма` и запасным вариантом по `ВерсияДанных`.
- Нативный разбор `.epf`/`.erf` в дерево BSL + JSON в формате, совместимом с `v8unpack` 1.2.6: модуль объекта, управляемые и обычные формы, группы, таблицы, команды, макеты (табличный документ, HTML, base64, двоичные, СКД).
- Автоматическое определение SQL-имён таблицы и полей справочника: ключи CLI, кеш в `state.db`, инструмент `db_table_fields` HTTP-сервиса базы (watch) или команда `BatchGetProcessingsStructure` через расширение (CLI). Повторное определение при ошибке `Invalid column name`.
- Режим watch: опрос журнала регистрации через HTTP-сервис базы, дедупликация событий по времени и хешу, выгрузка только при событиях изменения конфигурации, коммит и push, `git gc` по настройке, защита от второго экземпляра.
- Коммит и push после выгрузки (`--git-push`) с доменной авторизацией или логином и паролем; пароль в сообщениях git маскируется.
- Локальная SQLite `state.db` рядом с исполняемым файлом: состояние инкремента, кеш структуры хранения, журнал выгрузок.
- GUI на нативных контролах Win32: вкладки «Настройки», «Выгрузка», «Лог», «История», выбор базы из `bases.json`, окно подробностей записи журнала, растяжимая форма.
- Файловый лог watch с ежедневной ротацией.
