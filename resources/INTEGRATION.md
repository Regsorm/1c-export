# Интеграция `--export-processings` в базу 1С

Для каждой новой базы, где хотите использовать быструю SQL-выгрузку справочника `ДополнительныеОтчетыИОбработки` через `1c-export`, надо один раз доработать расширение `ВыгрузкаВсехВнешнихОбработок`. Никаких служебных `.epf` собирать не надо — всё работает через расширение, по тому же паттерну, что `BatchExportAddExt` и `BatchGetExtensionsList`.

## 1. Доработка расширения (один раз на базу)

Конфигуратор → открыть базу → Расширения конфигурации → `ВыгрузкаВсехВнешнихОбработок` → Открыть конфигурацию расширения.

### 1.1. Серверный общий модуль

`Общие → Общие модули → Расш2_ВыгрузкаДопОбработокИОтчетовСервер → Открыть модуль`.

В конец модуля вставить текст из [ПолучитьСтруктуруХраненияСправочникаДопОбработок.bsl.txt](ПолучитьСтруктуруХраненияСправочникаДопОбработок.bsl.txt) — процедура `ПолучитьСтруктуруХраненияСправочникаДопОбработок(ПутьКJSON)`, которая использует платформенную `ПолучитьСтруктуруХраненияБазыДанных()` и пишет имена таблицы/полей в JSON.

### 1.2. Модуль управляемого приложения расширения

`Открыть модуль управляемого приложения` → найти существующую процедуру `Расш2_ПриНачалеРаботыСистемы` (перехватчик с аннотацией `&После("ПриНачалеРаботыСистемы")`).

Внутри неё, рядом с блоками обработки `BatchExportAddExt` / `BatchGetExtensionsList` / `BatchImportAddExt`, добавить блок из [ManagedApplicationModule_patch.bsl.txt](ManagedApplicationModule_patch.bsl.txt):

```bsl
Если СтрНайти(КоманднаяСтрока, "BatchGetProcessingsStructure") <> 0 Тогда
    ПутьКJSON = ПолучитьПараметрИзC(КоманднаяСтрока, "Out");
    ...
    Расш2_ВыгрузкаДопОбработокИОтчетовСервер.ПолучитьСтруктуруХраненияСправочникаДопОбработок(ПутьКJSON);
    ЗавершитьРаботуСистемы(Ложь);
КонецЕсли;
```

### 1.3. Применить расширение

Сохранить расширение. В базе — `Конфигурация → Обновить конфигурацию базы данных (F7)`. На этом BSL-часть закончена.

## 2. Первый запуск

```bash
C:/1c-export/1c-export.exe \
    --server <СЕРВЕР_СУБД> \
    --server-1c <СЕРВЕР_1С> \
    --database <ИМЯ_БАЗЫ> \
    --auth-type password \
    --login <ЛОГИН_1С> \
    --password <ПАРОЛЬ_1С> \
    --ibcmd-path "C:/Program Files/1cv8/8.3.27.1786/bin/ibcmd.exe" \
    --output-path <КУДА_ВЫГРУЖАТЬ> \
    --ibcmd-db-user <SQL_ЛОГИН> \
    --ibcmd-db-pwd  <SQL_ПАРОЛЬ> \
    --export-processings \
    --verbose
```

Что произойдёт:

1. **Автодискавери.** Rust запустит `1cv8.exe ENTERPRISE /CBatchGetProcessingsStructure;Out=<json>`. Расширение перехватит команду, вызовет BSL-процедуру, запишет JSON с именами таблицы (`_ReferenceNNN`) и полей (`_FldNNN`). ~10 секунд, одноразово.
2. Имена закэшируются в `<output>/processings/_manifest.json` в блоке `source`.
3. **SQL-выгрузка.** Открывается TDS-коннект к MSSQL, лёгкий diff-запрос. По всем changed/new записям — запрос блобов, распаковка ValueStorage, сверка MD5 с `КонтрольнаяСумма`, запись `.epf`/`.erf` в `<output>/processings/<Вид>/<Имя>.epf`.
4. Итоговый отчёт: `new=X, changed=Y, unchanged=Z, deleted=W, failed=V`.

## 3. Повторные запуски

Просто тот же вызов — без `--rediscover`. Rust читает `source` из манифеста (без Enterprise), делает diff-запрос, скачивает только изменившееся. Ожидаемое время при нескольких изменениях — единицы секунд.

## 4. Если после обновления БСП начали падать SQL-запросы

Rust увидит ошибку `Invalid column name '_FldXXX'` (имена полей в БД сдвинулись). Тогда:

```bash
C:/1c-export/1c-export.exe ... --export-processings --rediscover --verbose
```

`--rediscover` форсирует повторный запуск discovery через расширение, переписывает `source` в манифесте новыми именами.

## 5. Fallback если расширение не обновлено

Если в целевой базе расширение без нового обработчика `BatchGetProcessingsStructure` — Rust упадёт с понятной ошибкой (JSON-файл не создан). В этом случае имена можно задать вручную:

```bash
... --export-processings \
    --processings-table _Reference112 \
    --processings-field-storage _Fld20583 \
    --processings-field-hash _Fld20584 \
    --processings-field-kind _Fld20585
```

Имена снять можно:
- через MCP 1С `get_database_storage_structure`;
- через Конфигуратор → Все функции → Служебные → Структура хранения базы данных → выбрать справочник `ДополнительныеОтчетыИОбработки`.

## 6. Структура вывода

```
<output_path>/
├── base/                          ← от --export-base (IBCMD)
├── extensions/                    ← от --export-extensions (IBCMD)
└── processings/                   ← от --export-processings (MSSQL)
    ├── _manifest.json             ← индекс: source + items[UUID]
    ├── ДополнительнаяОбработка/
    │   ├── ЗагрузкаОстатковSKU.epf
    │   └── КорректировкаДокументов.epf
    ├── ДополнительныйОтчёт/
    │   └── АнализПродаж.erf
    └── ПечатнаяФорма/
        └── УПД_ручная.epf
```

## 7. Первая верификация (sanity)

- `[N/total] имя: MD5=XXX` — обе цифры (из БД и вычисленная) должны совпадать.
- Открыть любой выгруженный `.epf` двойным кликом / через «Файл → Открыть» в 1С — должно работать.
- `v8unpack.exe file.epf out/` (если стоит в `C:\tools\v8unpack\`) — должно распаковать без ошибок.
- Второй запуск сразу — `unchanged = все`, время < 1 сек.

## Ограничения первой итерации

- **Защищённые паролем обработки БСП** — MD5 не сойдётся, запись пропустится с `[WARN]`, файл не запишется.
- **PostgreSQL** — не поддерживается.
- **Справочник `ВнешниеОбработки` (УПП)** — не поддерживается.
